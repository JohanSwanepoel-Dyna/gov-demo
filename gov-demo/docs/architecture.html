Issues

1

legacy-stub runs a vulnerable Log4j Critical

Log4j 2.14.1 is flagged for "Remote code injection in Log4j" and "Incomplete fix for Apache Log4j vulnerability". The Java services also have Tomcat, Spring, Jackson and Logback findings. The pod has 4 restarts, last exit 143 (SIGTERM, a liveness probe kill under saturation).

2

The assistant is the slowest path Warning

POST /api/assistant has p95 1.6 s against 162 ms for eligibility. 14% of chat calls (2,312 of 16,187 in 24 hours) end in content_filter. These are injection prompts from the load generator, so they are blocks working, not failures.

3

web: Node findings and a weak Davis root cause Warning

qs, body-parser, http-proxy-middleware and path-to-regexp have findings. When web degrades, Davis names "requests to unmonitored hosts" as the root cause and the problems arrive late and fragmented. This was accepted, not tuned.

4

payment-worker was killed once Warning

1 restart, last exit 137 (SIGKILL). The cause is not confirmed: it could be an out-of-memory kill or an external stop.

5

Assistant token use looks heavy Note

12.2M input against 0.88M output tokens (about 14 to 1). Each turn resends the system prompt and up to 20 messages, and the Locust assistant users reuse a conversation id, so 16,187 chats fall into only 3 conversation ids. History is capped at 20 messages, so memory does not grow without limit. Per-conversation views look unrealistic because each conversation has thousands of turns.

6

Telemetry gaps Note

Spans from the OneAgent-monitored web and legacy-stub have no service.name attribute, so they only resolve through the service entity (web, LegacyController). The OpenTelemetry services do carry it. The CVE id CVE-2021-44228 was not matched by my query, so it is unconfirmed in the Security view. Session Replay is unverified.
